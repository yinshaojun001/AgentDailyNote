# Agent 学习路线

先能解释一条请求如何运行，再学习如何让它在生产环境中可靠运行。进度由验收证据决定，不以阅读页数决定。

| 单元 | 核心问题 | 必须留下的产出 |
|---|---|---|
| Day 01：LLM + Harness | 谁决策，谁执行，谁保存状态？ | 职责图、练习答案、源码核对清单 |
| Day 02：[Context Engineering](../daily/day-02-context-engineering/README.md) | 从 LLM 机制到输入设计、预算和框架实现 | 八章教材、预算设计、1.0/2.x 对照与改进清单 |
| Day 03：ReAct 与终止 | 什么算一步，何时继续、失败或停止？ | 三种终止路径及循环上限实验 |
| Day 04：Tool、MCP、Skill | 函数、接入协议、任务知识如何分工？ | 同一能力的三种接入对照及权限边界 |
| Day 05：Runtime 生命周期 | 一次请求如何跨状态、模型和工具执行？ | 调用链、终止与保存时序、运行轨迹 |
| Day 06：Session、Memory、State | 哪些数据恢复对话，哪些恢复任务？ | 数据生命周期表与恢复实验 |
| Day 07：RAG | 检索结果是否支持答案？ | 小型查询集、召回与答案评价、rerank 对比 |
| Day 08：可靠性 | 超时、重试、并发和副作用怎么处理？ | 幂等设计、故障注入与恢复记录 |
| Day 09：可观测性与性能 | 延迟和成本花在哪里？ | trace 样例、模型/工具耗时拆分、优化前后数据 |
| Day 10：Eval | 修改后是否真的更好？ | 固定案例集、评分规则、失败分类及回归结果 |
| Day 11：安全与权限 | 不可信输入如何影响工具和数据访问？ | 威胁场景、权限检查点和对抗案例 |
| Day 12：Sub-Agent 与编排 | 多个 Agent 的收益是否超过协调成本？ | 单 Agent 基线与多 Agent 对比 |
| Day 13：综合设计 | 如何独立设计一个可恢复、可评测的 Agent？ | 规格、设计、实现任务和验收报告 |

## 每章的 SDD 模板

1. 用一段话写清场景与当前困惑。
2. 写 3—5 个能观察到结果的验收标准。
3. 标记已知事实与待验证假设。
4. 阅读官方资料，追踪当前项目固定版本源码。
5. 做一个能区分两种解释的实验。
6. 记录证据、修正结论、更新下一章重点。

## 第一项后续任务

Day 02 按八章正文建立完整上下文模型，再完成输入结构、预算、源码走读和实验设计。Runtime 生命周期移至 Day 05；Day 07 深入 RAG 实践，避免将本章概念介绍误当成已完成专题。

## 复习节奏

完成一章后立即闭卷讲解；隔一章重新回答前一章最薄弱的问题。每四章做一次综合题，把概念连到同一条执行轨迹上。
