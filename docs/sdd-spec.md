# AgentDailyNote 学习规格

版本：1.0；日期：2026-09-06。用户已批准轻量 SDD 方案，并指定公开仓库 `yinshaojun001/AgentDailyNote`。

## 目标与范围

把 Agent 学习变成可验证的迭代：每章先定义能力目标和验收证据，再写教材、练习和复盘。Day 01 建立 LLM 与 Harness 的边界，解释 ReAct 的位置，形成面向 AgentScope Java 项目的源码核对清单。

不在首期搭建网站、自动化流水线或修改业务项目。原始需求使用 agentDaily；以用户后续提供的 AgentDailyNote 为最终仓库名。

## 设计

根 README 提供导航和工作约定；docs 保存长期路线与规格；daily 按学习单元保存正文、练习和复盘。教材可以先完成，学习状态必须由实际作答与证据更新。

## 需求与验收

| 编号 | WHEN / THEN | 验收证据 |
|---|---|---|
| AD-01 | 当访问目标仓库时，应能公开读取默认 main 分支 | GitHub 元数据与分支 |
| AD-02 | 当打开首页时，应能找到目标、方法、目录和提交约定 | 根 README |

| AD-07 | 当发布教材时，应能在远端定位提交和全部文件 | 远端提交 SHA 与文件核对 |

## Day 01 学习验收

- L01：不看笔记，用自己的话解释 LLM 与 Harness 的职责，并举一个工具调用例子。
- L02：画出工具调用、结果回填、再次推理与终止的执行路径。
- L03：解释用户轮次、模型调用次数、ReAct iteration、消息条数的区别。
- L04：为项目中模型、循环、工具、上下文、持久化各找到一个源码证据；找不到则记录缺口。
- L05：解释工具执行成功但状态保存失败时，为什么不能盲目重试。

L01—L05 尚未验收。发布教材不自动勾选上述能力。

## 实施与检查记录

1. 核对目标仓库：公开，默认 main，初始为空。
2. 根据官方资料整理概念；保留当前项目版本与行为待核对标签。
3. 完成六份 Markdown 文件。
4. 发布前检查相对链接、文件完整性、空白错误及内部信息。
5. 通过已授权 GitHub 连接器发布，随后读取远端确认。

空仓库通过 Contents API 建立首个文件提交，再以该提交为父提交一次性加入其余课程文件。保留所有远端历史，不强制覆盖分支。
