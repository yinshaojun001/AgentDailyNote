# Day 02 练习与验收

先完整阅读[八章教材](README.md)，再作答。本次不采用逐句打断式问答。

## E1：解释机制（CE-01）
用订单案例解释参数、token、attention、上下文和应用 Memory。说明“每次调用需要全量上下文”哪里不准确。

验收：能区分推理与训练、有效输入与全部历史、缓存与业务记忆。

## E2：设计输入（CE-02）
为“订单 A 现在还能取消吗”画出输入结构，包含近期对话、实时结果、规则证据和工具 schema。标注来源、时效、角色与作用域。

验收：不把工具失败当成业务不存在；不把外部文档当授权；保持调用与结果关联。

## E3：选择技术（CE-03）
分别说明最新订单状态、公司政策、用户表达偏好、当前任务进度应由哪种机制提供。写一组正常与信息不足的 few-shot，解释 CoT 能帮助什么、不能保证什么。

验收：不把 RAG 与 Memory 当成互斥存储，不把示例事实当本次事实。

## E4：预算演算（CE-04）
按正文 32,000 token 算例，若新增工具结果为 12,000 token，给出下一轮预算调整方案；明确哪些内容不可直接删掉。

验收：算术闭合；工具 schema 计入；输出与安全余量保留；裁剪按语义与关联组；必需内容超限时明确替代路径。

## E5：源码走读（CE-05）
对照 1.0.12 sources.jar 的 prepareMessages、AutoContextHook.handlePreReasoning，以及 2.x 的 CompactionMiddleware.onReasoning，解释“存储内容”和“本次请求内容”怎样同步。

验收：标明版本；说出 1.0 getMessages 不触发压缩；说出 2.x messages/tools/options 的边界。

## E6：项目实验设计（CE-06）
设计一组能发现记忆注入被覆盖、重复注入、摘要丢掉否定条件的测试。给出输入、预期证据、实际捕获位置和成功判据，不需要先修改生产系统。

验收：区分已确认实现与待验证假设；用最终模型请求和任务结果共同评价。

## 评分

每题 0—2 分：0 为核心错误或未答；1 为概念正确但缺关键边界或证据；2 为满足验收标准。至少 10 分且 E4、E5 不为 0 才进入实践复核。当前没有作答成绩，也没有运行效果数据。
